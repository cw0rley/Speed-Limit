# Speed Limit

A cross-platform (iOS + Android) React Native + Expo app that shows the driver's current GPS
speed alongside the posted speed limit for the road they're on. Ships to the App Store and
Play Store; also targets **CarPlay** (full-screen custom sign) on iOS.

> **v2 direction (decided 2026-09-16) — see [`docs/ROADMAP.md`](docs/ROADMAP.md):** evolve this
> app (upgrade to Expo SDK 56+), replace HERE with **OSM first + TomTom Reverse Geocode fallback**
> via the Worker, make it **subscription-only** (RevenueCat), and ship a **CarPlay Live Activity**
> (no entitlement needed) instead of relying on the full-screen `MapTemplate`. This file still
> describes the app *as it is today*; update it as roadmap phases land.

> **Orient here first.** This file is the source of truth for how the app is wired. The root
> `README.md` is the short user-facing version (rewritten 2026-09-26 to match).

## Stack (current)

- **Expo SDK 54** (`package.json` → `expo: ~54.0.0`) — new architecture enabled.
- **React Native 0.81.5**, **React 19.1**.
- UI, drive mode, Live Activity sync and CarPlay live in **`App.js`** (~1,000 lines); the
  speed-limit lookup logic lives in **`lookup/`** (tested with `npm test`). Not using

## Key modules

  accuracy (`timeInterval: 1000`, `distanceInterval: 1`).
- `expo-keep-awake` — screen is kept awake **always**, via `activateKeepAwakeAsync(tag)` in a
  mount effect. There is no user-facing toggle anymore.
- `expo-haptics` — single warning vibration on the rising edge of "went over the limit"
  (tracked via `lastOverRef`).
- `@react-native-async-storage/async-storage` — persists the user's speed-alert thresholds
  under key `@speed_limit_thresholds`.
- `@iternio/react-native-auto-play` — CarPlay/Android Auto. Lazy-`require`d on iOS only so
  Expo Go (which lacks the native module) doesn't crash.
- `expo-task-manager` — defines the `speed-limit-drive` background location task (drive mode,
  iOS only; see CarPlay below).
- `@bacons/apple-targets` — generates the Live Activity widget extension from `targets/`.
- `modules/speed-limit-activity` — local Expo module (Swift) bridging JS → ActivityKit
  (`start` / `update` / `end` / `areActivitiesEnabled`).
- `expo-status-bar`.

## Speed-limit lookup (`lookup/`)

All lookup logic lives in **`lookup/`** (plain JS, no React Native imports, unit-tested with
`npm test` → `node --test lookup/__tests__/*.test.mjs`). `App.js` only creates the engine and
feeds it fixes from `handleLocation`.

- **`engine.js` — `createLimitEngine({ fetchArea, fetchTomTom, now, onLimit, onStats })`.**
  `update(fix)` per GPS fix; `onLimit(limit|null)` fires when the shown limit changes
  (`limit = { value, unit, source: 'osm'|'tomtom', road }`). Network + clock are injected so
  tests can drive it.
  1. **OSM area**: when the fix is within 250 m of the current box edge (or there's no box),
     download all drivable roads in a ~1.6 km box shifted up to 400 m ahead. Failures retry with
     back-off (15 s → 2 min). Every fix is then **matched to a road on the device**
     (`matchRoad`: distance + heading agreement + one-way penalty).
  2. **Matched road with OSM maxspeed** → shown (`source: 'osm'`).
  2c. **No maxspeed anywhere on the road, but the way names a statutory default**
     (`maxspeed:type` / `zone:maxspeed` / `source:maxspeed`) → resolved by `lookup/zoneLimits.js`
     and shown as `source: 'osm'` with `implied: true`; counted in `impliedSeconds`. Applied
     after 2b, and only for values the table can resolve honestly. See the 2026-10-28 lever B
     note under "Known gaps".
  2b. **Matched road without maxspeed, but another piece of the SAME road has one** → inherited
     from the **nearest** tagged piece within `INHERIT_MAX_M` (800 m) — `inferRoadLimits` /
     `roadKey` / `inheritedLimit` in `osmArea.js`; key = highway class + `ref` or `name`. Shown
     as `source: 'osm'` with `inferred: true`; counted in `inferredSeconds`. **Costs no paid
     lookup** — OSM splits roads into many ways and often tags only some of them. *Nearest*, not
     unanimous: see the 2026-10-28 note under "Known gaps" for why requiring every tagged piece
     to agree made this rule contribute almost nothing.
  3. **Matched road without maxspeed** → TomTom **once per road + direction** for the session
     (`wayTomTom` map). While TomTom is unavailable (spacing / capped / off) the road shows
     `--` — the previous road's limit is **never** carried over.
  4. **No road matched** (OSM covers the spot but has no road, or OSM is down) → TomTom per
     ~11 m cell, **only while moving**. While the first area is still downloading, nothing is
     asked. The answer is **carried forward** (`lastPoint`) for `POINT_VALID_M` (300 m) /
     `POINT_VALID_MS` (30 s) from where it was asked, and proposed under a key derived from the
     **value** (`cell:55mph`), not the cell — see the 2026-10-28 note under "Known gaps" for why
     the old per-cell key meant these answers were almost never displayed.
  - TomTom spacing: ≥ **8 s** between calls (`TOMTOM_MIN_INTERVAL_MS`), but moving onto a road
    we haven't asked about only waits `NEW_ROAD_MIN_MS` (3 s) — 30 s starved the display in town
    (real drive 2026-10: 12–21 calls/day against a 200/day cap, **20 % of moving time blank**).
    A road TomTom had no answer for is re-asked after `WAY_MISS_TTL_MS` (20 min) instead of being
    written off for the session. 10 min back-off after a Worker `429`/`503`
    (`TOMTOM_BACKOFF_MS`). Per-road lookups while stopped only if nothing is shown yet.
  - Display: a new road must match on **2 consecutive fixes** before its limit replaces the
    current one; fixes worse than 50 m accuracy are ignored for matching; if nothing is confirmed
    for 60 s while moving, show `--`.
  - **Stats** (`getStats` / `resetStats` / `restoreStats`): moving seconds split by source
    (OSM / TomTom / none), area downloads + failures, TomTom calls / hits / misses / back-offs /
    errors. `App.js` persists them to AsyncStorage (`@speed_limit_lookup_stats`, every 30 s) and
    shows them in **Settings → Lookup stats** — one collapsed row (`N min · N% blank`) that
    expands to the full table, with **Reset stats** at the top of it.
- **`areaStore.js`** — `createAreaStore(storage)`: keeps downloaded **OSM** areas on the device
  (AsyncStorage) bucketed by a ~1.1 km cell, max 15 records, 400 KB each, 14-day age limit. A
  repeated route needs **no download** (`areaFromStore` in stats). **`get(lat, lon, marginM)`
  must be called with `REFRESH_MARGIN_M`** (the engine does): with margin 0 it returns the very
  box the engine is trying to replace, which wedges the refresh — see the 2026-10-27 note under
  "Known gaps". **TomTom answers are never
  stored here** (their caching terms are still unanswered — case CS0014609).
- **`zoneLimits.js`** — `parseZoneLimit` / `zoneLimit`: statutory defaults implied by
  `maxspeed:type` / `zone:maxspeed` / `source:maxspeed`. Small, explicit table; unresolvable
  values return null rather than guessing. **Verify entries against statute before release.**
- **`osmArea.js`** — Overpass query (`convert` trims output to highway / maxspeed /
  maxspeed:forward / maxspeed:backward / oneway / name / ref / maxspeed:type / zone:maxspeed /
  source:maxspeed; ~75 KB for a suburban box), parsing
  (blank tags → `undefined`, motorways implied one-way), `matchRoad`, `areaBoxFor`. Endpoints
  `overpass-api.de`, then `overpass.kumi.systems`, 15 s timeout each, identifying `User-Agent`.
- **`tomtom.js`** — `GET ${PROXY_URL}/limit?lat&lon&heading` (5 s timeout) →
  `hit` / `miss` / `backoff` (429/503) / `error`.
- **`maxspeed.js`** — `parseMaxspeed` (`"50"` = km/h, `"25 mph"`, `"30mph"`, `"50 km/h"`,
  `kmh`, `kph`; implicit/conditional/multi values → `null`), `wayLimit` (direction-specific tags
  win), `convertLimit`. **`geo.js`** — haversine, local projection, point-to-segment, bearings.
  **`net.js`** — `fetchWithTimeout`.
- Imports inside `lookup/` use explicit `.js` extensions (needed by Node's test runner; Metro is
  fine with them).

**OSM coverage is poor in the US.** A central-NJ sample box (2026-09-17) had maxspeed on only
17 of 158 drivable ways (~11%) — none on ramps or primary/secondary roads. The public Overpass
servers also fail often (504s / timeouts observed repeatedly; `kumi.systems` never answered).
OSM alone cannot be the product; the commercial fallback (or a self-hosted OSM copy plus another
data source) is required.

**Background-safe by design (fix for "CarPlay limit stuck on 55", 2026-09-18):** with the phone
locked, JS timers (React effects with `setTimeout`, fetch timeouts) may not fire. So nothing on
the drive path depends on timers: the CarPlay template is pushed by `syncCarPlay()` from
`setDrive` (GPS fixes), and the engine runs **watchdogs on every fix** (area download abandoned
after 25 s → counted in `areaTimeouts`, TomTom after 12 s; late results ignored via generation
counters). The confirmation rule only refreshes the stale timer for **accepted** candidates
(previously every proposal did, so alternating candidates froze the old limit forever); a road
with the **same limit** is accepted immediately. The Live Activity blanks the **sign** too when
stale. Regression tests cover all of these.

**Drive-mode idle stop**: `handleLocation` switches drive mode off after 10 min without moving
faster than 2 m/s (`DRIVE_IDLE_STOP_MS`), so a forgotten session doesn't run background
location for hours.

### TomTom + the proxy Worker (`proxy/`) — NO-BILLING DESIGN

**Hard requirement from the user: they must never be billed again.** Safeguards (details in
`proxy/README.md` and the header of `proxy/worker.js`):

1. TomTom account on the **free plan, no credit card, no top-up — ever**. Over the free allowance
   (20,000 reverse-geocode requests/month) TomTom returns `429` instead of charging (TomTom FAQ).
   Paid "Pay As You Grow" is prepaid top-ups.
2. Worker **daily cap**: ceiling `MAX_DAILY_CAP = 600` (≤18,600/month); the `DAILY_CAP` var can
   only lower it. Each call is **reserved** in **D1** (one transaction) before it is made, and
   only if both the daily and per-IP counters have room — counters equal calls actually made.
   (KV was rejected: reads can be ~60 s stale and would undercount.)
3. Worker **per-IP cap** `PER_IP_HOURLY_CAP = 60`.
4. **Kill switch**: `TOMTOM_ENABLED = "false"` in `proxy/wrangler.toml` + `npx wrangler deploy`.
4b. **Access modes** (`TOMTOM_ACCESS`): `"test"` = test builds only, `"subscribers"` = only app
   user ids with an active RevenueCat `pro` entitlement (checked via RevenueCat REST with the
   `REVENUECAT_SECRET_KEY` secret, remembered in D1 `subscriber_cache` for 10 min, **fails
   closed**), `"both"` = either. The app sends `X-App-User-Id` (RevenueCat id) alongside the test
   token. Setup steps: `docs/STORE-SETUP.md`.
   Currently `"test"` → only requests with header
   `X-Client-Token` = Worker secret `TEST_CLIENT_TOKEN`. The app sends it only if built with the
   EAS **`testflight`** profile (`eas.json`, `environment: "preview"`), whose EAS env var
   `EXPO_PUBLIC_TEST_CLIENT_TOKEN` holds the same value (not in git; production env has none).
   Builds without the token never call TomTom (`lookup/tomtom.js`), and show nothing extra;
   token builds show "TEST BUILD" in the footer. **Never submit a `testflight`-profile build for
   App Store review** (it would carry the token).
5. **No shared server cache.** TomTom T&Cs §11.4 forbid caching "to serve multiple clients or
   users" (HERE's terms say the same, plus a 30-day max). Only the app's own per-device cache is
   allowed. (Also: the Workers Cache API does nothing on `workers.dev`.)
6. Any database error denies the call. Cloudflare Workers Free + D1 free tier: over-limit fails,
   doesn't bill (confirm the account is on the Workers **Free** plan).
7. **Open licensing questions for TomTom (get answers in writing before launch):** the free
   licence says "Evaluation Use only" while the FAQ allows commercial use; the paid licence
   excludes "Automotive Usage" (apps interacting with an in-car system — CarPlay may count);
   prepaid packages **auto-renew by default** — auto-renew must be turned OFF for a hard stop.

Worker routes: `GET /limit`, `GET /usage` (today's count vs cap), `GET /here-route` → **410**
(permanently off). Unit-parsing of TomTom's `addresses[0].address.speedLimit`
(`"25.00MPH"`, `"50.00KPH"`) is `parseTomTomSpeedLimit` (exported). Local test:
`npx wrangler dev --local` with a `.dev.vars` (gitignored).

**Do not** raise `DAILY_CAP` above the free allowance, add a payment method to TomTom, or route
around the Worker (no TomTom key in the app).

### HERE — removed after ~$1,000 of billing (history)

HERE Routing v8 billed ~$1,000 (420,787 transactions Jun 2–Aug 31 2026, usage export
`REPORT-116521`, saved at `C:\Users\pat\Downloads\REPORT-116521.txt`). Root causes: calls without
`departureTime` were billed as paid **Time Aware Routing** (the "1,000 free/day" tier never
applied); the old "40 m OR 15 s" throttle fired ~2,400 times/hour at highway speed; HERE was the
primary provider until commit `1953370` (Aug 5). Billing continued after that fix (160,664 more
transactions, peak 30,234 on Aug 7) — most likely old app builds still calling the proxy, and/or
the KV cache never populating. **Now:** all HERE code and the embedded key are gone from the app,
the Worker's `/here-route` returns 410 (so re-enabling the HERE key can't resume billing from old
builds), and the old KV namespace binding was dropped. **HERE is ruled out (decided 2026-09-21):** even contacting HERE requires creating an account
with a payment method, and its Base plan has no provider-side hard stop (alert emails only), so it
fails the no-billing guardrails. TomTom is the provider being pursued. The old
`HERE_API_KEY` Worker secret can be deleted; the key itself should be revoked on the HERE account.

## Subscription (`subscription/`) — RevenueCat

Decided 2026-09-17: **subscription only**, **$2.99/month and $24.99/year**, **7-day free trial**
(pending final confirmation), **existing free users do not keep free access**. Rollout: first a
**notice** release (banner + early trial), then the **required** release (paywall).

- **Config lives in `app.json` → `expo.extra.subscription`** (read by `subscription/config.js`):
  `mode` = `off` | `notice` | `required`, `startDate` (`YYYY-MM-DD`, shown in the notice),
  `iosApiKey` / `androidApiKey` (RevenueCat **public** SDK keys — safe to ship), `privacyUrl`.
  Use empty strings for unset values (Expo surfaces `null` extras as `{}`); `config.js` only
  accepts non-empty strings. Currently `mode: "off"` with nothing set.
- **`store.js`** — RevenueCat (`react-native-purchases`, lazy-required) as an external store
  (`useSubscription`): `initSubscriptions`, `loadOffering` (+ iOS trial-eligibility check),
  `purchase`, `restore`, `manageSubscription`, `getAppUserId` (for future Worker gating).
  Entitlement id **`pro`**. Status `disabled` (mode off / no key / no native module) never blocks
  the app. **`paywallRequired()` fails open** while loading or on store errors so a paying user is
  never locked out.
- **`Paywall.js`** — full-screen (no close) when locked, or a dismissible sheet. Annual first
  with "SAVE N%", per-month price, trial line only if eligible, CTA, renewal line, **Restore
  Purchases · Terms of Use (Apple standard EULA) · Privacy Policy**, store-specific legal text
  (App Review 3.1.1 / 3.1.2).
- **`SubscriptionNotice.js`** — banner in `notice` mode ("Speed Limit becomes a subscription on
  {date}…", "See plans" / "Not now"; snoozes 3 days).
- **`offer.js`** — pure copy helpers (trial length from App Store intro price or Play free
  phase, savings %, sort, legal text); tested in `subscription/__tests__` (part of `npm test`).
- **`App.js`**: `initSubscriptions()` on mount; when `paywallRequired`, the paywall *is* the app,
  drive mode is stopped and lookups are paused (`lookupsPaused`); Settings shows a
  **Subscription** section (status, See plans / Manage subscription, Restore purchases).
- **Worker gating is built** (`TOMTOM_ACCESS = "subscribers"`; `isEntitled` / `validAppUserId`
  in `proxy/worker.js`, unit-tested). Still needed from the user: RevenueCat project + App Store
  products, the `REVENUECAT_SECRET_KEY` Worker secret, the public SDK key in `app.json`, a hosted
  privacy policy URL, and the notice start date — all in **`docs/STORE-SETUP.md`**.

## UI (phone)

- Dark background (`#0b0d12`). Large current-speed readout (160pt portrait, 120pt landscape).
- Speed-limit "sign": black-bordered white box (US-style) with the limit number.
- **Portrait**: speed on top (dark), speed-limit sign below on a white panel, footer bar.
- **Landscape**: speed on the left (dark), speed-limit sign on the right (white panel).
- **Unit toggle** (MPH/KM/H) is in the footer, bottom-left. Both values display in the selected
  unit.
- **Settings gear** (bottom-right) opens a modal to configure **speed-alert thresholds** —
  three tiers of "N over the limit" → color (defaults: +3 yellow `#FFD700`, +8 orange `#FF8C00`,
  +10 red `#FF0000`). Persisted to AsyncStorage. The current-speed text color is driven by the
  highest applicable threshold via `getSpeedColor()`.
- **Over-limit state**: a warning haptic fires once on the rising edge. `isOver` uses a `+1`
  tolerance (`currentSpeed > displayLimit + 1`) to avoid boundary flicker. (The phone
  background does not turn fully red anymore — coloring is via the speed text; the *CarPlay*
  screen does turn its background red when over.)
- **Permission states**: `pending` (spinner), `denied` (full-screen message + "Open Settings"
  deep link), `granted` (the live UI). iOS re-denial is detected via
  `getForegroundPermissionsAsync().canAskAgain === false`.
- **Footer** (two rows): a one-line status (`GPS ±N m · Limits: OpenStreetMap|TomTom`, plus any
  error), then `[MPH]  [Show on CarPlay]  [⚙]`. The "Show on CarPlay" button is drive mode (see
  CarPlay). The user is still deciding whether it should stay a button or become automatic —
  leave it as a button until they say otherwise.

## CarPlay (iOS)

Apple **refused the Navigation entitlement** (Case-ID 21844634, 2026-09-16), so a full-screen
custom CarPlay view is not possible. The app holds the **Driving Task** entitlement
(`com.apple.developer.carplay-driving-task`, granted 2026-08-25) — template-only. Custom graphics
come from a **Live Activity**, which needs no CarPlay entitlement and shows on the CarPlay
Dashboard on iOS 26+. Work is on branch **`feat/carplay-live-activity`** — EAS build **26**
(commit `ce8c026`, 2026-09-16) compiled and was submitted to TestFlight; not yet tested in a car.

- **Head unit (template)**: `@iternio/react-native-auto-play` `InformationTemplate` with the
  limit + a drive-mode hint. Updates rate-limited to one per 10 s (Driving Task rule).
- **Live Activity** (`targets/live-activity/SpeedLimitLiveActivity.swift`, SwiftUI, extension
  deployment target iOS 18): `.supplementalActivityFamilies([.small])` is the CarPlay size —
  speed on the left, US-style (R2-1) sign on the right, red tint when over. Also Lock Screen and
  Dynamic Island layouts. `SpeedLimitAttributes` is duplicated in the Expo module and **must stay
  identical** in both files. `staleDate` = 30 s so a dead app shows `--`, not a frozen speed.
- **Drive mode** (the "CarPlay" footer button, iOS only): starts
  `Location.startLocationUpdatesAsync('speed-limit-drive', …)` with
  `showsBackgroundLocationIndicator` (works with When-In-Use permission; blue pill) and starts the
  Live Activity (must be done in the foreground). Stopping ends both.
- **State**: location/limit state lives in a module-level drive store (`setDrive`,
  `useSyncExternalStore`) fed by both the foreground `watchPositionAsync` and the background task;
  `syncLiveActivity()` de-dupes pushes with a 15 s heartbeat. `computeDisplay()` is the shared
  speed/limit/color math.
- **Native glue** (`plugins/withCarPlay.js`): driving-task entitlement (removes `carplay-maps`),
  `UIApplicationSceneManifest` scene configs, and the `getRootViewForAutoplay` AppDelegate hook.
- **Unknowns to test**: how often CarPlay actually redraws the Live Activity at 1 Hz app updates;
  battery use; App Review justification for background location.
- iOS prebuild can't run on Windows — the EAS build is the first real compile of the Swift code.
- `ios.appleTeamId` (`N27NV97893`) is set in `app.json` for apple-targets signing.

- **Fixed 2026-10-27 — "no limit the whole way home" (drive of 2026-10-26).** Stats showed
  48 % blank over 29 min with **81 "maps reused from device"** and 90/91 TomTom calls answered,
  so neither provider was at fault. Two bugs compounded:
  1. **`areaStore.get` used margin 0** while `areaNeedsRefresh` uses `REFRESH_MARGIN_M` (250 m).
     Boxes are shifted up to 400 m *ahead* of travel, so driving back along the same road puts
     you near each stored box's **trailing** edge: inside it (margin 0) but inside the refresh
     margin too. Every fix asked the store, got the same box back, and reset `areaFailures` — so
     no new box was ever downloaded and the car always left the box with nothing to replace it.
     The outbound leg was fine because its boxes were freshly fetched and shifted the right way.
  2. **Leaving a box with its replacement in flight asked nothing at all** — the cell fallback
     was gated on `areaContains || areaFailures > 0`, both false in that window, so the display
     held the last road's limit until the 60 s stale rule blanked it. Now a download still
     running after `AREA_GRACE_MS` (6 s) lets TomTom answer by cell; a fast download still costs
     nothing.
  Both have regression tests (`lookup/__tests__`, verified to fail without the fixes). Drive mode
  also now **resumes itself** when the car moves again after the 10-minute idle stop (foreground
  only, 5 s of movement, and only when the idle timer was what stopped it — a stop the user or
  the paywall asked for stays off). That was *not* the cause of the blank drive, but it did mean
  the Live Activity was dead for the trip home.
- **Fixed 2026-10-28 — paid lookups that never reached the screen.** Same drive: **90 of 91
  TomTom calls answered, but only 8 % of moving time showed a TomTom limit**. The per-cell path
  (step 4 above) was broken twice over, and only while *moving*:
  1. `askTomTom` only **stores** the answer; the proposal happens on a later fix that reads
     `cellTomTom.get(cell)`. Cells are `CELL_PRECISION = 4` ≈ **10 m**, so at 25 mph+ the car is
     out of that cell before the answer returns and the entry is never read again. The call was
     paid for and thrown away.
  2. The proposal key was `c:${cell}`, which changes every ~10 m, so the **2-fix confirmation
     could never be satisfied** — two consecutive fixes never carried the same key. A point
     answer could only ever be displayed when it happened to equal what was already shown
     (`sameLimit` shortcut) or when nothing had ever been shown (`current.key == null`). Worst
     case: once the 60 s stale rule blanked the display, **nothing on this path could bring it
     back** for the rest of the drive.
  Now the most recent answer is kept as `lastPoint` and re-proposed while the car is within
  300 m / 30 s of where it was asked, under a **value-derived key** so a steady reading holds the
  display and a changed one still has to agree on two fixes. **The call rate is deliberately
  unchanged** (a refresh still goes out whenever `TOMTOM_MIN_INTERVAL_MS` allows) so the next
  drive's stats measure the display fix alone — carrying a point answer further to spend less is
  a separate decision, and `POINT_VALID_M` is the dial.
- **Raising OSM-only coverage (opened 2026-10-28).** A production build never calls TomTom
  (`lookup/tomtom.js`: no test token and no app user id → `backoff`), so **a free store release
  is OSM-only**. On the 2026-10-26 drive that would have been 44 % of moving time (OSM 42 % +
  inherited 2 %). Three levers, none needing a paid call or a licensing answer. Measure before
  building: `node --no-warnings tools/osm-coverage.mjs <lat> <lon> [radius]` reports each one
  **length-weighted** (what you actually drive) for a real area.
  - **A — inherit from the nearest tagged piece, not by unanimity. DONE 2026-10-28.**
    `inferRoadLimits` used to collapse each road to one limit and drop the road entirely if any
    two tagged pieces disagreed. A road long enough to legitimately step from 45 to 55 therefore
    taught the app **nothing along its whole length** — and those are the roads most driving time
    goes on, which is why `inferredSeconds` was only 2 %. It now keeps the tagged pieces with
    their geometry and `inheritedLimit(area, way, p)` takes the nearest one within
    `INHERIT_MAX_M` (800 m — the accuracy/coverage dial), so a stepping limit is followed instead
    of discarded. Regression test verified against the old rule. **Trade-off:** where inheritance
    now answers, no TomTom call is made, so a wrong guess shows instead of a paid lookup; in a
    free OSM-only build that is strictly better than blank, and it also cuts quota use.
    *Possible refinement:* prefer shared-node connectivity over raw distance — the Overpass
    `convert` currently drops node ids, so that needs a query change first.
  - **B — statutory-default tags. DONE 2026-10-28.** `maxspeed:type` / `zone:maxspeed` /
    `source:maxspeed` say "there is no sign; the limit is the statutory default", which is the
    real legal limit. They are now downloaded (`mt` / `zm` / `sm` in the `convert`) and resolved
    by **`lookup/zoneLimits.js`**, applied in `matchRoad` **after** `own` and `inherited` — a
    surveyed sign is evidence, a statutory default is our own table, so the table's blast radius
    stays limited to roads where nothing else is known. Counted separately as `impliedSeconds`
    (Settings → "implied by road type") so the next drive measures this lever on its own.
    - Values stating a number (`US-NC:35`, `DE:30`) are used as given — nothing to get wrong.
    - Named classes need a table entry: `GB:nsl_single|nsl_dual|motorway`, `DE:urban|rural`,
      `US-NC:urban` (35) / `US-NC:rural` (55). **The US-NC pair and anything added later must be
      verified against statute before a public release** — a wrong number here is worse than a
      blank sign.
    - Bare `US:urban` / `US:rural` are **deliberately unresolved**: the default varies by state.
      `tools/osm-coverage.mjs` now lists zone values present in an area that `zoneLimits.js`
      cannot resolve — that is the actionable list, each entry being road that lights up for one
      verified table addition.
  - **C — per-class defaults** (e.g. all `residential` → 25 mph). Biggest coverage, biggest
    accuracy risk, and statutes vary by state (NC's unposted municipal default is 35, not 25).
    Only worth it if the tool shows a class dominating the remaining blank length. Do last, if
    at all.
  - The tool also prints `maxspeed` values `parseMaxspeed` rejects. If something common shows up
    there (`signals`, `variable`, conditional forms), that is a cheaper and safer fix than any
    of the levers.

## Running

```bash
npm install
npx expo start          # Expo Go for the phone-only UI (CarPlay needs a dev/prod build)
```

CarPlay and the native config plugin do **not** work in Expo Go — you need an EAS
**development build** (`eas build --profile development`) on a real device to exercise CarPlay,
and Apple's entitlement before it will sign.
